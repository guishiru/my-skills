# 执行细则：读数据，跑分析

## 步骤

1. **不改动原始文件。** 所有输出写到原文件旁边新建的文件夹里，或者写到工作目录。
2. **数据画像。** 先列出：行数、字段及类型、主键、时间跨度、缺失比例、重复行、取值范围、异常值。字段含义不清楚的，猜一个最可能的含义并标注出来；只有当它会影响结论时，才去问用户。
3. **采集检查**（来自《数据驱动：从方法到实践》）：
   - 关键事件是在前端采集的，还是在服务端采集的？前端采集会丢数据，涉及交易、支付这类关键事件，以服务端数据为准。
   - 用的是不是全埋点（不写代码、自动采集所有点击和浏览）？全埋点只能采到这类浅层行为，采不到业务属性。
   - ID 有没有打通？没打通时，同一个人在不同设备上、登录前后会被算成多个人，导致重复计数，行为链路也会断开。
   - 分析的时间段内，埋点有没有改过版本，口径有没有变过？
   - 4 项逐项写出结论，最后写进报告的“口径与方法”一节。从数据里判断不了的，写“需要确认：……”，不能跳过不写。
4. **质量关卡。** 出现以下任一情况，先停下来告诉用户：
   - 主键重复；
   - 关键字段缺失超过 5%；
   - 时间上有断档；
   - 混入了测试数据；
   - 样本量不够支撑结论。
5. **计算。** 每个结论都附上：数值、对比基准、样本量；需要时附显著性检验或置信区间。A/B 测试先检查两组的实际分流比例是否符合设计，比例不对，结果就不可信。A/B 测试的结论以"差值 + 置信区间"为主，也可以换成贝叶斯的说法："新方案更好的概率是多少"。
6. **稳健性检查。** 下面几项至少做两项，确认结论不会因此改变：
   - 换一种口径重新算；
   - 去掉异常值再算；
   - 按时间分段看；
   - 按主要维度拆开看，防止辛普森悖论（整体趋势和各组趋势相反）。
7. **作图。** 每张图只讲一个结论，图的标题直接写结论。
8. **保留可复现的材料。** 保留计算代码和中间结果表。

## 报告模板

```
## <一句话结论>

**结论**：1–2 句，带数字和对比基准
**可信度**：高 / 中 / 低，理由（样本量、方法、稳健性检查的结果）

### 关键发现（不超过 3 条，每条：结论 + 数字 + 图）
### 建议动作（分立即 / 短期 / 长期，每条写清：谁来做、做什么、怎么衡量效果）
### 口径与方法（指标定义、数据范围、采集检查 4 项的结论、用了什么方法、做了哪些稳健性检查）
### 局限与下一步（还有哪些解释没被排除；要确认的话，需要补什么数据或做什么实验）
```
