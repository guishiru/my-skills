# 用图表说话（chart-talk）

一张图只讲一个结论。读者扫一眼标题就该知道你想说什么，看一眼图就该相信它。

本 skill 有两个模式：

- **出图模式**：从数据到一张（或一组）能说清结论的图。载体：Excel 原生图表、网页看板、静态图片（PNG）。
- **复核模式**：审别人的图或汇报页，输出问题清单和改法。

先判断用户要哪个模式；拿不准就问一句。

---

## 出图模式：五步，顺序不能换

**配色放在最后。** 大多数糟糕的图，是先挑了颜色和图形，才去想要说什么。

### 第 1 步　写下结论（一句话）

在动手之前，用一句话写出这张图要证明什么，并把它作为图的标题。

- 主题式标题（不要）：「2026 年各渠道订单量」
- 结论式标题（要）：「9 月小程序订单首次超过 App，占比达 41%」

结论要具体到对象、方向和幅度。数据不支持任何结论时，如实写成观察（「各渠道差距在 5% 以内，无明显分化」），不要硬造。

**用词不能超过数据。** 只有相关性时，不写“全靠”“导致”“带动”“因为”，写“同时出现”“越…越…”“高留存城市都在增长”；样本少（如 8 个城市）要在副标题注明。
副标题写口径：时间范围、单位、数据来源、统计口径（如“已剔除退款单”）。

→ 结论怎么写、常见错误：`references/message-first.md`

### 第 2 步　判断比较类型（五选一）

结论里的关键词决定比较类型：

| 比较类型 | 结论在说什么 | 关键词 |
|---|---|---|
| **成分** | 部分占整体多少 | 占比、份额、构成、百分之几 |
| **项目** | 几个对象谁大谁小 | 排名、最高、高于、低于、差不多 |
| **时间序列** | 随时间怎么变 | 增长、下降、波动、趋势、环比、同比 |
| **频率分布** | 数值落在各区间的多少 | 集中在、分布、X 到 Y 之间、区间 |
| **相关性** | 两个变量是否一起变 | 随…增加、与…有关、越…越… |

运营场景的专用类型（实际 vs 目标、漏斗转化、留存矩阵、构成变化）见 `references/choosing-a-form.md`。

### 第 3 步　选图形

| 比较类型 | 首选 | 可选 | 避免 |
|---|---|---|---|
| 成分 | 100% 横向条形 / 单根堆叠条 | 饼图（≤5 块，且只比一个整体） | 环形图比相近数值、3D 饼图 |
| 项目 | **横向条形图，按大小排序** | 点图、表格 | 竖柱配长类目名、彩虹色 |
| 时间序列 | 强调**每期的量**（对目标、对比各月）→ 柱形；强调**走势、交叉、多系列** → 折线（不论点数多少） | 面积图（单系列） | 时间轴不等距、断开不标注 |
| 频率分布 | 直方柱形（柱间无缝隙） | 折线分布 | 区间宽度不等却不说明 |
| 相关性 | 散点图 | 成对条形图（读者不熟悉散点时） | 双坐标轴硬凑相关 |

**先问：这需要图吗？** 只有一个数 → 指标卡（大数字 + 变化 + 迷你趋势）；几个核心数 → 一排指标卡；类目超过 7 个且每个都重要 → 表格或表格加图。

**强调**是最常被忽视的手法：要说“某一个”的故事时，把它涂成主色，其余一律灰色。两个主角就用两种分类色，其余灰色。

**量 + 率**（订单量和转化率、GMV 和毛利率）是双坐标轴最常见的诱因：改用成对横向条形（两边共用类目顺序），或者散点图。

→ 完整选图规则：`references/choosing-a-form.md`

### 第 4 步　配色与标注

配色按“颜色在干什么”分四种：

- **分类**（区分系列）：用默认色板，按固定顺序取色，不循环、不自造第 9 色
- **顺序**（大小或阶段，如漏斗、等级）：单一色相，由浅到深
- **发散**（高于/低于基准，如达成率）：两种冷暖相反的颜色，中间点用灰色
- **状态**（好/预警/危险）：保留专用，必须配图标或文字

**一页多图时，先列“页面颜色表”**（每个对象、每种含义对应一个颜色，全页通用），再逐张画图。

**用脚本校验配色，不要凭肉眼判断色弱能否分辨：**

```
python scripts/check_palette.py "#2563c9,#d9711c,#12a08a" [--bg "#18191c"] [--all-pairs] [--ordinal]
```

把图里所有颜色一起传入（灰色会自动识别为弱化色，只查对比度）。有“失败”必须先修正，“警告”按提示补救（通常是必须加数据标签）。散点、地图、小多图加 `--all-pairs`；顺序色和热力色加 `--ordinal`。

标注原则：细线条、浅网格；折线和密集的点只标端点、最值、主角；类目 ≤12 的条形/柱形可以全部标数字并去掉数值轴。文字用灰黑色，不用系列色。

→ 默认色板与配色规则：`references/color.md`
→ 线条、标签、图例规范：`references/marks.md`

### 第 5 步　按载体落地，然后亲眼检查

- **Excel 原生图表** → `references/excel.md`（openpyxl，含目标线、单点高亮、选择性数据标签）
- **网页 / 看板** → `references/web.md`（单文件 HTML，ECharts 或内联 SVG，含悬停、表格视图、深色模式）；外部库加载不了时用 `assets/svg-charts.js`
- **静态图片（PNG，贴进 PPT、文档、群聊）** → `references/static.md`（matplotlib，含中文字体）

出图后**必须渲染并查看**：Excel 先转成 PDF 或 PNG 再看，网页要截图。检查标签是否重叠、是否被裁切，坐标轴是否完整，标题是否就是结论。然后逐条对照 `references/anti-patterns.md`，命中任何一条都要修改。

## 不可违反的规则

1. **标题是结论，不是主题。**
2. **一张图只讲一个结论。** 两个结论就画两张图。成对条形（两个面板共用类目、共同证明一个结论）算一张图。
3. **不用双坐标轴。** 量级不同的两个指标：拆成两张图，或都换算成指数（基期 = 100）放在同一个坐标轴上。
4. **柱形图和条形图的数值轴从 0 开始。** 折线图可以不从 0 开始，但要在副标题里说明。
5. **颜色跟着对象走，不跟排名走。** 筛选后剩下的系列保持原来的颜色。
6. **分类色最多 8 种。** 超过的部分合并为“其他”，或者拆成小多图。
7. **饼图最多 5 块，且只在“成分”比较时使用。**
8. **数字要能对上。** 各分项加起来等于总计，百分比合计约等于 100%，同比和环比的口径要写清楚；同一个数在标题、指标卡、图上的写法（小数位）保持一致。
9. **结论用词不超过数据。** 相关不写成因果，小样本要注明。

## 复核模式

用户给一张图、一页 PPT 或一个看板，让你“看看有没有问题”时：

> **整份汇报（文字论证 + 图表）且装有 critical-reading 时，走“联合复核”**：论证归 critical-reading，图表归本 skill，同一问题只报一次，合并成一份报告。流程见 `references/review.md` 末节。


1. 先还原：这张图想说什么？（如果看不出来，这本身就是第一个问题）
2. 按四层检查：**结论层 → 选图层 → 误导层 → 视觉层**
3. 输出：总评一句话 + 问题表（严重程度 / 问题 / 为什么是问题 / 怎么改）+ 改后的标题和图形建议
4. 用户需要时，按出图模式重画一版

→ 检查清单与输出模板：`references/review.md`
