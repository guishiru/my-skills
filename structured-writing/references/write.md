# 写模式：五个步骤

> 何时读：用户要一份还不存在的文档，或只给了素材。对应《结构思考力》主干流程。

五步顺序不可跳：描述问题定方向 → 基于目标定主题 → 纵向结构分层次 → 横向结构选顺序 → 形象表达做演示。

---

## 第一步：描述问题定方向

只在问题本身还没说清时做；用户已明确要写什么就跳过。

用 5W2H 把问题描述完整（见 `tools.md` 工具 2），重点说清 **R1 现状** 和 **R2 期望**。两者都要可衡量：「效率低」不行，「单据平均处理 3.5 天，目标 1 天」才行。R1 到 R2 的差距，就是这份文档要解决的问题。

## 第二步：基于目标定主题

**2.1 目标**：先问清场景（何时、何地、给谁看），再定目标。目标是「说完之后希望对方**做什么**」，不是「让对方了解」。三条检验：是具体行为吗？从对方角度出发吗？当场能达成吗？
- ✗ 让领导了解项目进展　✓ 让领导批准把上线时间推到 11 月

**2.2 主题**：主题是源于目标的**结论**，不是话题。要简单（一句话）、准确（无「若干」「相关」「进一步」）、有利益（对读者有什么用）。
- ✗ Q3 工作总结　✓ Q3 目标达成 112%，但获客成本上升 30%，建议 Q4 收缩投放渠道

**2.3 序言 SCQA**：把读者拉到同一起点，再自然引出主题。

| 要素 | 写什么 | 硬约束 |
|---|---|---|
| S 情景 | 双方都熟知的背景 | **只写读者已知或一定认同的事**，否则他会出戏 |
| C 冲突 | 背景下出现的问题或变化 | 必须和 S 直接相关 |
| Q 疑问 | 冲突引出的问题 | 通常不写出来，但心里要清楚 |
| A 回答 | 你的观点 | **A 就是 2.2 的主题**，不一致说明前面错了 |

自检：把 S 和 C 念给读者，他会自己问出 Q 吗？不会，就是 C 没写到位。

## 第三步：纵向结构分层次

下一层的每一条，都是对上一层那个问题的回答。

**3.1 自上而下（已有观点，要讲清楚）**：站在读者角度设想他会问什么（What / Why / How 为主，完整版见工具 2），逐个回答。每一层的答案都必须是结论，不是话题：「成本问题」不行，「成本超支主要来自物流」才行。不同类的问题配不同类的答案，不要一个答案同时回答两个问题。

**3.2 自下而上（手里只有散事实）**：周报、述职、复盘必须走这条。罗列 → 分类（现成的筐见工具 3）→ 每组归纳一句带判断的结论。两种概括：行动型（做到了什么结果）、描述型（这些事共同说明什么）。杜绝「三点体会」「几个问题」这种底下是空的主题句。

实际多为两者结合：先自上而下搭框架，材料不支持时再自下而上调整。

## 第四步：横向结构选顺序

**演绎 vs 归纳**：要**说服**用演绎，对方要**快速拿要点**用归纳。演绎常用式是「现象 → 原因 → 方案」，最常见的错是**把现象当原因**（「退货率上升」是现象，「抽检比例从 5% 降到 2%」才是原因）。推理链不超过 4 步、一段里不超过 2 个结论，超了改归纳。

**归纳三种顺序**：时间（流程、阶段）、结构（区域、部门、人财物）、重要性（轻重缓急）。

**MECE**：不重叠（「线上渠道 / 电商平台」重叠）、不遗漏（只讲华东华南，漏了华北）。三个捷径：2×2 矩阵、套现成模型（工具 3）、用「其他」兜底。

## 第五步：形象表达做演示

产出 PPT 或口头汇报时读 `presentation.md`。

---

## 输出：先出骨架，停下来等确认

起草前至少问清两件事：**读者是谁、看完要他做什么**；**读者已经知道哪些背景**（决定 S 写什么）。

第一轮只输出骨架：

```
【中心思想】一句话，必须是结论不是主题
【关键句】3-4 条，每条都是完整结论句
【序言 SCQA】情景 / 冲突 / 疑问 / 回答，各一到两句
【建议篇幅】约 N 字，M 个章节
（素材缺口标【待补：……】）
```

然后问：「骨架对吗？要调整哪里？确认后我展开成稿。」确认后再成稿，成稿前过一遍 SKILL.md 的论证类比四条。
