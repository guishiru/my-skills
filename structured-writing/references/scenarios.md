# 四类职场写作场景

> 何时读：判断出属于哪一类之后，只读对应的那一节。对应《结构化写作》方法篇。

判断不清时看动词：告知 / 说明 → 一；总结 / 汇报 / 复盘 → 二；申请 / 建议 / 争取 → 三；方案 / 选型 / 决策 → 四。

---

## 一、清晰传递信息

**典型**：通知、制度说明、产品介绍、流程说明。**目标**：读者准确知道这件事，不用再来问。

1. **设计标题**：标题包含结论。✗「关于系统升级的通知」✓「系统 10 月 8 日 0:00–6:00 停机升级，期间无法下单」
2. **撰写序言**：C 通常很弱，简化成「背景一句 + 变化一句」，直接给 A。
3. **展开内容**：按 What → Why（读者不问可省）→ How（我该怎么做、找谁）。**结尾必须有行动指引**，哪怕是「无需操作」。

## 二、准确总结工作

**典型**：周报、月报、述职、复盘。**目标**：读者知道你做了什么、结果如何、你怎么判断。

⚠️ **必须自下而上。** 先定中心思想再往下填，会写成自我美化的空文。

1. **成果分类**：全部罗列，先不筛选；再按业务线、职能、达成情况或阶段分组（选一种）。
2. **排序整理**：给上级看优先按重要性，他只看前两条。
3. **概括总结**：每组归纳一句带判断的结论，再归纳出全文中心思想。
   - 行动型：✗「推进了供应商管理工作」✓「完成 12 家供应商分级，淘汰 2 家，质量投诉环比降 35%」
   - 描述型：✗「三个项目情况汇报」✓「三个项目都卡在同一处：跨部门数据接口没打通」

### 最高频的失败：写动作，不写结果

第 3 步被整个跳过，通篇「推进了 X」「开展了 Y」，读者判断不出这周顺利还是卡住了。

| 伪结果 | 为什么不算 | 改成 |
|---|---|---|
| 推进研发排期 | 动作，推成了没有？ | 排期已确认，9/17 多端上线 |
| 本周可以看到初步效果 | 预告，到底看到没有？ | 上线首周质检通过率 82%，符合预期 / 数据未回收，下周给 |
| 决策推进 4 个新项目 | 动作 + 空洞类别句 | 4 个新项目已定方案并进入排期 |

**判定方法**：挑出每条的动词。推进、开展、跟进、对接、梳理是动作动词；完成、上线、确认、下降 X%、达成是结果动词。动作动词占多数就是命中。合格的写法有交付物、有状态、有时间：「MCP 已建成，9/17 Agent 接口上线后可测试」。

**周报最小骨架**：
```
【本周结论】一句话，带判断
【关键进展】2-3 条，每条是结果不是动作
【风险与卡点】有才写
【下周重点】2-3 条，可验收
```

## 三、充分说服他人

**典型**：立项、预算、资源申请、提案。**目标**：读者同意并给出你要的东西。

1. **明确观点**：开门见山说要什么，具体到多少、何时、谁做。✗「随着业务快速发展……」（第四段才说要加人）✓「建议 Q4 为售后质量组增编 2 人，预算 XX 万。理由如下。」
2. **疑问回答**：站在对方位置逐个回答——为什么需要？为什么是现在？为什么是这个量？钱从哪出、投入产出比？有没有更便宜的替代？风险是什么、失败怎么办？**主动回答后两条**，自己先摆出反对意见比等对方提强得多。
3. **逻辑归整**：优先用演绎（现象 → 原因 → 方案），严格区分现象和原因。

## 四、有力汇报方案

**典型**：完整方案、技术选型、决策建议书。**目标**：读者在你给的选项里做决策。

和第三类的区别：**要给选项**。领导要的是「A/B/C 选哪个」，不是「同意不同意」。

走完 `write.md` 五步骤，并用这个结构：
```
【结论与建议】推荐哪个 + 要的决策是什么
【背景与问题】R1 现状 → R2 期望 → 差距
【方案对比】2-3 个选项，同一套维度横向比（成本、周期、风险、可维护性、对现有系统影响）
【推荐理由】为什么选这个，以及为什么不选另外两个
【实施计划】谁、何时、做什么、里程碑
【风险与应对】
【所需支持】人、钱、决策，具体到数
```

两条要求：对比维度必须一致，不能 A 讲成本、B 讲技术；**不要做假选项**凑数衬托，一眼就会被看穿。「为什么不选 B」比「为什么选 A」更重要。
