# 改模式：按金字塔重构现有稿件

> 何时读：用户给了稿子并明确要求「改」「重写」「按金字塔重构」。只分享没说要改的，走 `audit.md`。

## 流程

1. **内部诊断**：按 `audit.md` 跑一遍（含数据自洽），不输出完整报告，结论浓缩进改动说明。
2. **只拆不加**：把原文拆成事实、理由、结论三份清单。原文没有的信息一个字都不进清单。
3. **重搭金字塔**：有结论的把结论提到顶层，其余按以上统下挂下去；没结论的自下而上归纳，并告诉用户「原文没有明确结论，我从材料里归纳的是 XX，不对请指出」。同层选一种顺序，超 7 项上提归并。
4. **改标题和序言**：无信息标题改成结论句；补或重写 SCQA，S 只留读者已知信息。
5. **过论证类比四条**。

## 输出格式

```
【改动说明】3-5 条，只说结构层面动了什么、为什么（删掉的内容必须交代）
【改后全文】
【改前改后对照】| 位置 | 改前 | 改后 | 原因 |，只列 3-6 处结构性改动，不逐字对照
```

## 改模式特有的规则

- **保留语气**：口语化的仍然口语化，「咱们」「搞定」照留，不加「兹」「特此」「现将……汇报如下」。改成公文腔是越界。
- **结构需要但材料没有的**：标 `【待补：这里需要一个支撑数据】`，不自己编。原文观点你不同意也照原样保留。
- **删减先想一遍**：是真冗余还是没看懂它为什么在？看不懂就保留并标注。
- **篇幅持平或更短**：改完长了 50%，多半是在加自己的话。

## 特殊情况

- **原文结构本来就没问题**：不为交付而改，直接说「结构清楚，只调了三处标题」，给出那三处。
- **原文太散、几个主题互不相关**：不硬凑，建议拆成几份，或问用户这次讲哪一个。
- **材料明显不足**：先出骨架加待补清单，问用户补充。
