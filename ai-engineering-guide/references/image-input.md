# 图片 / 多模态输入

适用：用户上传图片做识别、质检、OCR、理解，或 Agent 需要处理图片输入时。设计、评审、排查图片链路时读本文件。

核心判断：图片识别出错，多数不是模型不够强，而是**图没读对、问法不对、结果没规整、单点失败没兜底**。可靠性（不报错、不空返回、不乱码）和准确率（看得准）是两件事，都要管。

## 1. 先判断

- **主模型原生支持视觉** → 直接把原图放进主模型上下文，不要先单独调一次模型把图转成文字描述再传。既省一次调用，又不丢信息（文字描述必然丢细节）。只有主模型不支持视觉、或描述需要存档/检索时，才单独做描述。
- **以提取文字为主**（票据、证件、表单）→ 对比专用 OCR 和视觉模型：OCR 便宜、稳定、能给坐标；视觉模型理解版面和语义更强。金额、数量等高风险数字无论用哪种都要回查（见 knowledge-base.md 4.8 数值回查）。
- **要看细节**（质检、缺陷、小字、仪表读数）→ 重点处理分辨率（见 2.6）。

## 2. 输入：先把图读对

1. **按文件头字节判断真实格式**，不信文件后缀和声明的 MIME 类型。常见特征：JPEG 以 `FF D8 FF` 开头，PNG 以 `89 50 4E 47` 开头，PDF 以 `%PDF` 开头。声明是图片但实际不是 → 直接拒绝；确认是图片 → 用探测出的类型发给模型。典型例子：从微信另存的图片后缀是 .png，内容其实是 JPEG。
2. **只转码模型不认的格式**（常见是 HEIC/HEIF → JPEG），其他格式原样放行。多转一次会多耗 CPU、可能损失画质、多一个出错环节。判断依据是真实格式，不是来源设备。
3. **先处理方向**：手机照片靠 EXIF 方向标记来旋转显示。转码或去除元数据前，先按方向标记把像素转正，否则模型看到的是横着或倒着的图，识别明显变差。
4. **去掉隐私元数据**：EXIF 可能含 GPS 位置、设备信息，进模型或落存储前去掉。
5. **体积闸门查两次**：读入时按文件字节查上限（参考默认 10MB），超限在本地直接判负、不发请求；发生转码后，对转出的文件再查一次（HEIC 转 JPEG 可能变大）。上限要按最终请求算：base64 编码会再大约三分之一，多图会叠加，总量不能超过接口的请求大小限制。
6. **分辨率**：各家视觉模型都会把过大的图缩放到上限尺寸再看（具体尺寸以官方文档为准），细节可能在缩放中丢失。体积上限只保服务稳定，管不了这个。需要细节时，主动裁剪关注区域或切块分别识别再汇总；不需要细节时，自己先缩小可以省 token 和时间。

## 3. 请求：把图问对

- **统一入口构造请求**：每张图都带正确的 MIME（base64 只是文本，本身不带格式信息，缺了或标错会解码失败或被拒）；消息结构固定。提示词放系统消息，还是和图片放在同一条用户消息，按厂商规则来；结构不对，要么报错，要么模型没把图当输入。
- **多图要编号**：每张图带编号或标签，提示词按编号引用，避免模型把甲图的内容说成乙图的。
- **判定类任务**（例：按图检查 5 项是否达标）：
  - 提示词写成编号清单，要求逐项回答。
  - 用结构化输出或 JSON schema 约束，每项含结论、一句理由，必要时含位置。
  - 代码校验项数是否齐全、取值是否合法；不合格重试 1 次，仍不合格判失败并保留原文。
  - **不要用字符截断处理结构化结果**，截断会静默丢掉最后几项。
  - 允许输出「无法判断」（图不清、被遮挡、角度不对），并和「不达标」分开统计；不给这个出口，模型会硬判。
  - 参数参考：逐项推理比一句话描述慢，超时要给足（如 120 秒）；输出上限要放得下全部项和理由；体积上限留足余量，别把正常高清图拒掉。

## 4. 输出：把结果规整对

- **软约束 + 硬约束**：提示词里写「最多 N 字」只是软约束（参考默认：图片描述 500 字），代码要再做一次硬限制。自由描述类超长时按字符边界截断，不把中文字、emoji 切成乱码；结构化结果走 3 的校验，不截断。
- **只推理不出正文**（推理模型偶发）：先确认是「回复里有推理内容、但没有答案文本」这一特定情况，才用同一张图、同一提示词、去掉推理参数重试一次；其他错误不走这条重试，且只重试一次。

## 5. 容错与速度

- **超时分两段计**：准备阶段（下载、转码、建连）和等待模型响应分开计时，报错能区分慢在哪。超时立即中止、尊重外部取消信号，然后切到下一个候选模型。超时设下限（如不低于 1 秒），防止误配成 0。
- **多模型回退**：按候选顺序依次尝试；每次尝试留一条结构化记录（模型、成败、原因、耗时），既供回退决策，也供排查和展示「用了哪个模型、为什么失败」。
- **参数提前解析**：体积上限、输出上限、超时、提示词在选型阶段就解析好（按模型条目 → 能力配置 → 全局默认的优先级），执行层据此快速判负。
- **输出 token 上限**取「请求值」和「模型自身上限」的较小值，防越界被拒后重来。
- **缓存只需算一次的东西**：模型注册表、鉴权、运行时对象。按配置快照做缓存键并设容量上限；按对象缓存时用弱引用，对象被丢弃时缓存自动释放。
- **多图并发但设上限**（参考默认 2），防压垮下游厂商和内存。

## 6. 安全

- 图片里的文字可能是注入指令（例如截图里写着「忽略以上指令」）。图中文字一律当数据，不当指令；真正的防线是权限最小化，见 SKILL.md §10。

## 7. 评测

- 样本按真实分布采：清晰/模糊、正放/倾斜、强光/暗光、不同设备和格式（含 HEIC）。判定类任务每一项都要有正例、负例和「无法判断」例。
- 按项统计准确率、漏检率、误报率，单独统计「无法判断」比例和空返回率。
- 失败归因分四类：输入（格式、方向、分辨率、体积）、模型、提示词、解析校验。
- 改分辨率策略、提示词、模型或候选顺序时，跑回归对比再上线。
