# 用户增长

### 激活路径设计

核心策略（7 条）：
1. 设计流程前先定义激活事件：对比留存用户和流失用户的行为，找出与留存关联最强的动作作为候选，再用实验验证推动这个动作确实能提升留存。
2. 围绕“到达价值的最小路径”设计：列出注册到体验核心价值之间的所有步骤，删掉不必要的，再重建流程。
3. 首次使用只追求一个成功结果，高级功能往后放；动手做优先于看教程。
4. 先选激活模式（免费增值、免费试用、付费试用、退款保证、咨询），再设计引导路径。
5. 用进度感推动完成：清单 3–7 项，按价值排序，快速见效的放前面；替用户预先完成一步能提高完成率（经典研究中完成率从 19% 提到 34%）。
6. 某一步没人做时，用 Fogg 行为模型（动机 × 能力 × 提示）诊断缺哪一项。
7. 先优化漏斗中落差最大的一步；评估激活看“到付费的转化 + 90 天留存”，不看线索数量。

### 推荐与联盟计划

核心策略（7 条）：
1. 先判断产品有没有天然传播潜力：协作、通信、对外产出类产品做产品内传播；后台、基础设施类不硬做病毒传播。
2. 客户推荐计划适合低客单价、自助购买、高信任的产品；联盟计划适合触达自有渠道够不着的受众和高客单价产品。
3. 推荐循环是“触发 → 分享 → 被推荐人转化 → 奖励”；邀请放在用户刚体验到价值或达成里程碑之后，不放在注册时。
4. 分享入口优先放在产品内、用户正在用的地方；具体哪种分享方式效果最好，用自己的数据比较。
5. 双边奖励（推荐人和被推荐人都有）通常转化更高；奖励表述用显示数字更大的那种：原价低于 100 元用百分比（如 25 元商品减 10 元，写“立减 40%”），原价 100 元以上用金额。
6. 先分情况诊断：很少人推荐，就改邀请时机、简化分享、提高曝光；推荐来了不转化，就改落地页和被推荐人激励。
7. 用推荐渠道的获客成本、LTV、ROI 评估效果，并和其他渠道的同期客户比较留存和 LTV。

### 流失预防

核心策略（7 条）：
1. 主动流失和被动流失（支付失败）分开统计、分开处理；被动流失通常最容易修复，先算清它在自己总流失中的占比。
2. 取消流程按“触发 → 单题退出调查（5–8 个选项）→ 按原因匹配挽留方案 → 清楚确认 → 取消后留召回路径”设计，始终保留“继续取消”的入口，不用暗黑模式。
3. 挽留方案要和取消原因对上：嫌贵的给限时折扣，用得少的给暂停选项，功能不够的引导到对应功能。折扣力度和暂停时长用实验来定，避免大额折扣把用户训练成“取消换折扣”。
4. 在用户点取消之前先预警：用登录频率、功能使用、工单、账单页访问等信号做健康分，权重用历史流失数据校准，按分段干预。
5. 支付失败按类型处理：软拒付（如余额不足）分几次重试；硬拒付（如卡失效）不重试，直接请用户换卡。重试、催缴邮件、暂停服务三条时间线要统一排好，不能互相冲突。
6. 评估挽留效果看被挽留用户之后的 LTV，不只看挽救率；基准用自己的历史数据。
7. 取消流程的实验一次只测一个变量。

### 邮件序列

核心策略（6 条）：
1. 一封邮件只做一件事、只放一个主要行动按钮。
2. 先给价值再提要求；看重相关性而不是发送量，按分群发送。
3. 序列长度和节奏按销售周期和产品复杂度定：前期密、后期疏，具体封数和间隔用退订率和转化率测出来。
4. 动笔前先定好触发条件、转化目标和退出条件；触达配合产品内引导，不重复产品里已有的内容。
5. 用户超过自身正常使用间隔仍不活跃时启动召回序列，目标是赢回用户，或者清理名单。
6. 主题行清楚优先于巧妙，在主流客户端里不被截断。

### A/B 测试

核心策略（7 条）：
1. 每个测试先写可证伪的假设：基于什么观察、做什么改动、预期什么结果、针对哪类人群、用什么指标衡量。
2. 一次只测一个变量；只定一个与业务价值挂钩的主指标，另设次要指标和护栏指标。
3. 开测前先用样本量计算器算好样本量（例：基线 5%、要检测 10% 的相对提升，95% 置信、80% 功效，每组约 3.1 万），中途不偷看、不提前停。
4. 按事先定好的分析方法和停止规则解读；同时报告效应量和置信区间；不显著时不靠延长测试去“凑”显著。
5. 事先没计划的细分人群发现只算探索性结论，要用新测试确认。
6. 把实验做成持续机制：用 ICE（影响、信心、难易）排序，保持稳定的实验节奏；赢了的实验要总结成可复用的模式。
7. 护栏指标的检查频率和停止规则要事先定好；需要中途多次查看时，用序贯检验等专门方法。

### 增长循环

核心策略（6 条）：
1. 先明确核心价值动作、单次动作产生的价值、有没有网络效应，再评估适合哪类增长循环。
2. 按“新用户从哪里来”区分循环：用户主动邀请（推荐 / 病毒）、用户产出的内容被别人看到（内容循环）、协作中自然拉人（协作循环）、用户的付费或使用带来更多投放预算（付费循环）。
3. 逐项设计：触发点、激励、分享的便捷程度、邀请到激活的转化率、单个用户重复参与的频率。
4. 估算循环系数（人均邀请数 × 邀请转化率），再结合每一轮循环的时长判断增长速度。
5. 先把最自然、杠杆最高的一个循环做透，再叠加其他循环。
6. 不同循环的增长速度和带来的用户质量不同，按各自带来用户的留存和 LTV 比较取舍，不预设哪种最好。

### 北极星指标

核心策略（4 条）：
1. 先判断业务类型：注意力型、交易型，还是生产力型。
2. 北极星指标必须是单一的、以客户价值为中心的领先指标，不能是收入或 LTV。
3. 用 7 条标准检验候选指标：易懂、以客户为中心、体现可持续价值、与愿景一致、可量化、团队能直接推动、是领先指标；并用历史数据验证它确实领先于留存或收入。
4. 再配 3–5 个输入指标：更容易推动，能直接带动北极星指标，能指明优化重点。

### 同期群分析

核心策略（5 条）：
1. 先校验数据：同期群标识、时间维度、缺失值；明确留存口径（某一天是否活跃、某段时间内是否活跃，还是之后是否还活跃）。
2. 计算各同期群的留存率和功能采用率，用热力图和留存曲线找流失点；观察期没满的近期同期群单独标出，不和完整同期群直接比较。
3. 横向对比各同期群，识别早期流失、后期变化和季节性；比较时考虑每群样本量，差异要看置信区间。
4. 同期群的个数和每群样本量都要足够，才能得出结论。
5. 定量发现之后，用访谈、会话回放等定性研究解释原因，再设计实验验证。

### 增长模型

核心策略（6 条）：
1. 先看产品特性，判断主增长引擎是搜索、付费、销售还是用户传播，集中做透这一个，不在多个渠道上平摊精力。
2. 用闭环画增长（上一轮的产出是下一轮的输入），不用单向漏斗。
3. 在表格里把增长变量量化并互相勾稽，用数学对账检验假设。
4. 增长停滞时，沿获客 → 激活 → 留存逐段找断点；评估投放看增量（反事实），不看相关性。
5. 如果少数用户贡献了大部分价值，并且事先无法判断谁会成为这样的用户，就优先降低门槛、扩大尝试的人数。
6. 第二种增长方式（如在销售之外叠加产品自助）何时加入，看第一种是否已稳定、对手是否在用第二种方式抢客；不预设越早越好或越晚越好。

### 激活指标与引导

核心策略（7 条）：
1. 激活指标必须用数据验证：达到这个里程碑的用户，留存或转化要显著更高；大部分人都达到了而留存仍然低，说明门槛定得太低。
2. 引导只推动一个与长期留存关联最强的核心动作，注册后马上提示用户去做。
3. 尽快让用户第一次感受到价值，去掉人工审核、必须约销售电话等挡住试用的环节。
4. 用向导和个性化引导代替空白页，降低上手时的认知负担。
5. 步骤取舍：不影响首次价值的步骤一律删减或延后；对后续使用效果关键的设置（如个性化偏好、关键配置）保留，并解释为什么要做。
6. 按角色分别设计 aha 时刻：个人使用者、团队协作者、付费决策者各不相同。
7. 可以用行为设计手段（强制选择、目标梯度、首日承诺）提高完成率，效果用实验验证。

### 留存与活跃

核心策略（7 条）：
1. 先把留存做扎实，再加大变现力度。
2. 用分群留存曲线衡量留存（看曲线在哪里走平），不看总活跃数；活跃不按“打开 App”这类噪音事件算；免费和付费用户分开看。
3. 首次体验是关键的留存节点，优先消除早期摩擦。
4. 对高频、习惯型产品，可以用连续打卡这类损失厌恶机制培养习惯；低频产品不适用。
5. 让产品越用越好，用户离开时损失越大（数据、配置、关系沉淀）。
6. 用流失率算出增长天花板（新增 = 流失时，规模不再增长）；流失高时靠获客解决不了问题。流失是否“严重”，和同类业务及自己的历史比较。
7. 把支付失败造成的非自愿流失和主动流失分开处理。

### 推荐与口碑

核心策略（5 条）：
1. 推荐计划是加速器，造不出需求：先看自然流量和口碑带来的新用户占比是否已经可观，再决定投入多少做推荐计划。
2. 口碑来自产品在更快、更便宜或更易用上明显优于用户现在的做法。
3. 根据产品本身的社交行为选择传播方式（口碑、邀请、使用中被看到），用 K 因子衡量（人均分享次数 × 分享转化率）。
4. 奖励在被推荐人完成激活里程碑（如首单）之后再发，并控制在获客成本上限以内。
5. 在用户满意度最高的时刻展示推荐入口；双边市场要同时重视供给侧的推荐。

### 增长实验

核心策略（6 条）：
1. 先定北极星指标；按影响和成本（ICE/RICE）给实验排序，并把实际能看到这个改动的用户比例算进去。
2. 新渠道、新想法先花小预算测有没有效果信号，有信号再加码。
3. 用随机对照实验衡量增量，作为判断效果的主要依据。
4. 追求实验速度，胜出的越早上线越好；同时定期回看已上线改动的长期效果，排除新奇效应和实验之间的相互影响。
5. 什么时候必须做 A/B 测试：改动影响大、可能有负面影响、流量足够时必须测；改动小、风险低、流量不够时可以直接上线，并监控核心指标。
6. 早期用简单工具快速迭代；减少审批层级，成功和失败的经验都要制度化地分享。

### 用户分群

核心策略（8 条）：
1. 先定决策再选属性：只有当这群人会得到不同的优惠、渠道、节奏，或被排除在发送之外时，才建这个分群。
2. 分群定义写成别人能复现的规则：属性、算子、阈值、观察窗口、源系统、缺失值处理。
3. 阈值用相对自身分布的方式表达（分位数、客单价倍数、中位复购间隔倍数），不用绝对金额。
4. 建群前先在“可触达基数”上计数：太小就放宽条件或并入相邻分群；属性填充率低的只能当试点。
5. 多个分群同时发送时用互斥分区加优先级；不在任何群的“剩余人群”必须指定去向和负责人。
6. 判断分群有没有用，看它与“其余人群”在同一处理下的目标指标差异，并给出置信区间；与自身历史 8–12 个周期比较。
7. 定期复审：每个分群只能在保留、重切、合并、退役四者中选一；定义改动处标记序列断点。
8. 用来“排除不发”的规则，要从被排除的人里随机留一部分照常发送，用来验证。

### RFM 分群

核心策略（8 条）：
1. 计算前先确认订单已跨渠道合并到同一个人；评分方向写进定义。
2. 每条轴选一种切法：有业务事实依据（如购买周期、包邮门槛）就按事实切，否则按分位数切。
3. 近度（R）的边界取购买间隔分布的倍数：用整个购买人群的回购曲线（包括尚未复购的人）来估，不只用已复购的人，避免低估间隔。
4. 每条轴分几档由自身分布决定，起点 3 档；多数人只买过一次时，频次只切“1 次 / 多次”；拉不开差异的轴直接删。
5. 先给每个格子计数再命名，太小的格子沿“区分最弱的轴”合并；每组只有一条路线、一个负责人。
6. 没有购买记录的人移出网格，按“中位首购时长”分成新来的和来了很久仍未购买的，分别处理。
7. 近度实时读，频次和金额定期重算；新边界上线后的第一次重算只作基线，不触发消息。
8. 控制指标：“陈旧分组发送率”（发送时关键轴已经变了的消息占比）。

### 欢迎与激活

核心策略（8 条）：
1. 按“承诺”（用户以为留下联系方式能换到什么）列出入口；承诺和目标动作都一致的入口才能共用一个序列。
2. 第一条触达先兑现承诺，兑现前不索取任何东西。
3. 每个序列只设一个能实时看到的目标动作，动作一发生序列就中断。
4. 序列长度看首购时间分布：取累计首购曲线明显变平的时间点（大部分最终购买者已经完成首购），而不是固定 30 天，也不是中位数。
5. 触达节奏前密后疏，充分利用新用户早期意向最高的时段；具体间隔和次数用实验定，以退订率和首购率为准。
6. 激活事件写成“Y 天内完成 X 次动作”：先定性访谈出候选，再用双向判据加覆盖率挑选，最后用随机实验证明因果。
7. 事先定好四种结局（中断、窗口耗尽、退订、合法依据过期），各有明确去向。
8. 控制指标：各入口到达批次在窗口内的首次动作率，分母是全部到达记录。

### 复购

核心策略（8 条）：
1. 复购间隔按“人 × 具体商品”计算，不按整张订单。
2. 间隔来源按阶梯取：个人历史 → 商品的“单件可用天数 × 数量” → 全库中位数 → 用户自述；记录用的是哪一档。
3. 提醒日 = 间隔 − 决策所需时间 − 配送时间；由事件触发重算；用户自己推迟的日期优先于模型。
4. 二购时长在整个首购批次（包括从未回购的人）上测；回购者不足一半时，改用回购曲线变平的点来定窗口。
5. 二购窗口开头留静默期（配送 + 首次使用），再切成几个独立时间段，每段一次触达。
6. 论据默认按成本从低到高排：服务 → 产品 → 金钱，每次触达只给一个主要行动；用对照组验证“先给钱会不会教用户等折扣”。
7. 加购先剔除已拥有的、缺货的、不符合约束的；更贵的替代品只推给客单价高于中位数的人；每单最多一个让利型加购。
8. 控制指标：首购批次的二购率，分母是整个批次；退货期结束后才定稿。

### 流失预警与召回

核心策略（8 条）：
1. 只认一个“合格动作”（如购买）；不再购买和不再打开点击分开，不混在同一个分群。
2. 流失阈值按品类的复购间隔分布来定：取大部分正常复购已经发生的分位点（如 80% 或 90% 分位），而不是中位数加一个模糊的“容差”。
3. 先剔除不在范围内的人（不再需要该品类、明确拒绝、自然离开、购买周期太长），剩下的人太少就不做。
4. 早期预警：从已流失者回溯构建信号，分“相对自身常态的下降”和“警报行为”两类；信号权重和触发门槛要在另一批数据上验证（留出验证集），行动前二次确认。
5. 预警只触发诊断性动作（询问、提供帮助），不给钱，以免教会用户“沉默换折扣”。
6. 召回顺序：第一条先问原因再谈钱；论据逐级加码；渠道免费在前、付费在后；起点 3–5 次触达。
7. 事先声明结束日期，五种结局各有去向。
8. 控制指标：回归率 = 窗口内完成合格动作的人 ÷ 全部越过阈值的人；配常设对照组，防止召回变成长期打折渠道。

### 会员 / 忠诚度计划设计

核心策略（8 条）：
1. 先选形态（即时折扣、延迟积分、付费会员），用三项检验决定：品类对即时价格还是累积更敏感、定价政策是否允许直接降价、发行方与兑付方能否结算；结算不了就否决积分模式。
2. 积分生效延迟 ≥ 退货窗口 + 回传时滞；兑付比例上限用毛利最差的品类测；承诺成本 = 面值 × 兑付率。
3. 上线前和促销政策变化时，检查“禁兑商品占比 × 促销期占比”，防止积分无处可花。
4. 积分有效期至少覆盖一个典型购买周期（再加季节余量），上限由负债承受能力决定。
5. 等级边界按自身分布设，资格基础按想推动的指标选；顶层是否真的被激励，要用对照组验证。
6. 每个等级的奖励先测两档大小：事先设好“多少差异以内算效果相同”和所需样本量，只有确认效果相同时才取小的那档；结果不确定就继续测，或保留大的那档。
7. 推荐奖励只为达到门槛的首个付费订单付费，上限 = 订单毛利 × 获客可用比例，退货窗口后发放，加三道防刷限制。
8. 修改在线计划：先分清是设计问题还是执行问题 → 写下预测 → 在一个切片上测 → 迁移时保留等级和余额 → 同时看触发指标和毛利。
