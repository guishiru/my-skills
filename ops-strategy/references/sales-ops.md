# 销售运营

### 收入漏斗设计

核心策略（5 条）：
1. 数阶段之前先定三件事：模型的主要用途（流程、计划、预测三选一）、分析单位（线索、购买小组或账户）、售前在哪结束；收入边界建两条（签约用于记账，首次价值用于算回收期）。
2. 转化率按同期群（同一批进入的记录）计算，用 4–8 个季度的窗口，按“进入该阶段的数量”计，不按当前在库数；每个比率都标注口径、样本量和来源；不用 CRM 自带的默认概率。
3. 外部基准只用来提示“该查一查”，不拿来定目标；拆分维度由样本量决定。
4. 阶段数按销售模式控制，越重的销售模式阶段越多（经验起点：产品自助 3–4 个，高触企业销售 6–8 个）；只有真实的操作需要才加阶段。
5. 自下而上的漏斗计划必须和自上而下的目标对账，差距写成数字；跨部门交接按“纸面映射 → 统一定义 → 双边 SLA → 系统计时”逐级推进。

### 管道阶段定义审计

核心策略（5 条）：
1. 核心检验：每个阶段的退出标准必须是买方做了、说了或同意的事，并且有可查的记录，两位经理各自判断能得出同样结论。
2. 先把管道分为开发型、交易型、事务型再评判；每个阶段对应到买方的采购任务，对不上的是“伪装成阶段的销售动作”。
3. 修复顺序按性价比排：先改写退出标准 → 加检查 → 补证据字段 → 最后才裁撤或新增阶段；季度中途不迁移。
4. 迁移时只停用旧值、新增新值，绝不重命名或删除。
5. 验收：抽样让两人各自判断阶段，一致率 ≥ 90%，样本量要足以让这个比例可信（建议 30 单以上）；再看各阶段在库占比是否与历史停留时间相符。

### 销售管道卫生

核心策略（6 条）：
1. “有效活动”指阶段、成交日期或金额发生变化；打电话、发邮件只作为第二触发条件。
2. 先按停滞时长切出陈旧层（< 90、90–180、180–365、> 365 天）；陈旧金额超过 20–30% 时，先集中清理、不追责，再开始严格执行。
3. 按细分市场算各阶段停留天数的中位数，基线用全部已结束的单（成交和丢单都算），超过 1.5 倍（中小客户）到 2 倍（企业）就标记。
4. 成交日期被反复推迟是滑单的强信号：第二次推迟就升级给经理检查，推迟 3 次及以上考虑淘汰；用多个信号区分“在推迟”和“已死”，并用自己的历史数据验证这条规则的准确度。
5. 每个被标记的单只有一个处置（关单、转培育、回退、改期、保留）、一个负责人和一条理由；不自动关单。
6. 只查预测会用到的字段：完整率目标 90–95%，底线 80%；必填字段控制在 5–7 个。

### 销售预测诊断

核心策略（6 条）：
1. 每个根因只归入数据、行为、需求三类之一；区分数据和行为靠一个问题：“CRM 显示之前，你就知道这单已经死了吗？”
2. 先量化偏差：同时给出带正负号的误差和绝对误差，避免正负抵消。
3. 从期初快照重建当期，不用期末数据评判；每一块钱缺口都归到具体交易和唯一主因，归因覆盖 ≥ 90%。
4. 需求因素最后剥离：数据和行为修正后剩下的缺口，才是真实的需求不足。
5. 修复按“归因金额 ÷ 修复成本”排序；滑单集中在业绩考核门槛附近时，优先改薪酬设计。
6. 回测：同一套规则放到更早的一期，要能抓到 ≥ 80% 的实际滑单，同时误报率要在团队能处理的范围内。

### 交易审批台

核心策略（6 条）：
1. 审批同时管五类让步：价格、付款条款、服务、合同风险、安全承诺；只管价格，让步就会转移到其他四类。
2. 设 3–4 个审批层级，底部有自动批准线，再垫一条政策毛利底线；最惠国条款、无上限责任等任何层级都不能批。
3. 阈值优先用“各折扣档的赢率”推导：在多给折扣已经不再提升赢率的地方设底线；比较时按交易规模、竞争情况分层，避免“难单才给大折扣”的混杂。
4. 申请里最重要的字段是“拒绝会怎样”；不完整的申请直接退回；审批超时逐级升级，每个审批人有代理人。
5. 每个例外都有到期日；反复出现两个评审周期以上的例外，要么转成标准政策，要么明确拒绝。
6. 周期、赢率、折扣率、毛利、泄漏五项一起看；周期报中位数和 P90，不报均值。

### 线索评分

核心策略（6 条）：
1. 拟合度（能不能买）和参与度（要不要买）分两个轴打分；硬性排除直接剔除，不靠扣分。
2. 先审数据覆盖：某字段覆盖率低于约 70% 时，未知值记 0 分，并单独追踪这批人的转化。
3. 信号从结果反推：在 12–24 个月的全部线索上，比较转成商机或成交的和没转成的信号频率，只保留有真实提升、且在打分时点已存在的信号。
4. 初始权重按销售模式定：销售主导的偏重拟合度，产品自助的偏重参与度；每类信号设上限，然后用回测结果校准。
5. 阈值先按销售承接能力定，再参考转化率；回测要求最高档转化率至少是基线的 2 倍。
6. 上线前要有销售书面签字，模型做版本管理，并提前约好 60 天后的复盘。

### 线索分配

核心策略（6 条）：
1. 改规则前先埋全时间戳链：捕获 → 合格 → 决策 → 分配 → 通知 → 接受 → 首次动作。
2. 先修线索与账户的匹配（域名优先）；匹配率低于约 90% 或重复率高于约 5% 时，先清洗再谈分配。
3. 优先级阶梯，第一个命中即生效：法规合同 → 指名账户 → 在途商机 → 现有归属 → 区域 → 产品或技能 → 产能 → 公平分配 → 兜底队列。
4. 先建兜底队列，再做归属；算法默认用带在岗检查的轮询，灰度期观察到问题才升级。
5. 加接受时钟：超时没人接就改派备份人；上线走沙盒、测试包、灰度，禁止直接改生产规则。
6. 响应时效 SLA 用自己的历史数据定，不引用“5 分钟 / 21 倍”这类流传数字。

### 销售到客户成功交接

核心策略（5 条）：
1. 交接设计归结为六项决策：触发事件及门禁、必传数据、载体、两个时钟、会议形式、带接受环节的问责链。
2. 从最轻的做法起步：先做 CRM 字段门禁加分配规则、现场交接会；重点大客户再加内部同步会和逐单交接文档。效果按交接后客户的上线速度和早期流失来评估。
3. 交接包的前四项必填（通话录音、客户目标、销售承诺、商务条款），不填就阻断交接；没人看的字段直接删。
4. 载体只能是结构化字段或系统事件，不能是聊天或邮件；CS 可以带原因码拒收。
5. 默认阈值：门禁完整率 ≥ 95%，首次接受率 ≥ 90%，成交后 1 个工作日内完成内部交接。

### 客户健康分

核心策略（6 条）：
1. 先定义要预测什么（流失事件、实体层级、预测窗口），再讨论信号。
2. 指标按席位或用户数归一化；工单和满意度看趋势，不看绝对数。
3. 权重用多变量方法（如逻辑回归）按“流失客户 vs 留存客户”推导，避免相关信号被重复计权；每类信号设上限，关键人离职能单独拉低分档。
4. 分数的水平和趋势一起打（下滑中的 75 比稳定的 60 更危险）；连续两次读数都变才换档。
5. 只设三档，红档大小按团队的干预能力定；每档绑定动作、负责人和 SLA。
6. 验收：红档流失率 ≥ 基础流失率的 3 倍；用精确率和召回率评估，不用准确率。

### 客户流失信号

核心策略（5 条）：
1. 区分领先和滞后：付款失败、降级申请出现太晚，只算“确认型”，不算领先信号。
2. 每个信号写全操作定义：事件、阈值、窗口、对比基线、归一化方式。
3. 回看流失前 30/60/90 天的信号状态，按“相对基础流失率的提升倍数、提前期、覆盖率”排序，再除以搭建成本。
4. 上线门槛：提升倍数 ≥ 2，提前期中位数 ≥ 30 天，覆盖 ≥ 25% 的历史流失；信号组合合计覆盖 ≥ 70%。
5. 只算客户主动发起的行为，排除 CSM 外联造成的“互动”；NPS 有响应偏差，排在产品行为之后。

### 收入 KPI 框架

核心策略（6 条）：
1. 交付一棵能对账的指标树：父节点必须等于子节点的和、积或比；复合指标要拆出分子分母。例：净收入留存率（NRR）=（期初收入 + 扩张 − 收缩 − 流失）÷ 期初收入 = 毛收入留存率（GRR）+ 扩张率。
2. 每个分支只有一个负责人，跨团队指标在交接边界处切开。
3. 每个负责的指标至少配一个反向护栏指标（重要指标可以配 2–3 个）；指标连续上升而护栏同时下降，视为刷数并升级处理。
4. 领先还是滞后，相对被预测的指标判断；每个层级最多 5–7 个指标。
5. 默认做到“驱动树”（顶层指标加 3–5 个驱动指标）；出现归属争议时才升级成完整树。
6. 北极星指标不选收入本身，选一个领先于收入的指标。

### 收入报告

核心策略（6 条）：
1. 核心指标 5–6 个，最多 8 个，优先选能改变决策的；至少有一个留存类指标；每期沿用同一组指标，换指标要加注。
2. 起草前先锁定定义：公式、包含与排除、数据源、负责人、时间窗口。
3. 先和财务对账再写叙述；标题数字必须和财务认证的一致。
4. 结论先行：首页写本期结论、最大驱动因素、应对措施、需要的决策；用变动桥代替净额，用分布代替均值。
5. 没达标也不能让董事会意外：提前披露，说明原因，给出负责人，重述预测。
6. 董事会约 2/3 的时间用于前瞻性决策；预读材料提前 3–4 天发出。

### 收入泄漏

核心策略（5 条）：
1. 守恒检验：进入数 = 推进数 + 有原因的丢单 + 有原因的取消资格 + 正常在途数 + 残差；只分析残差。
2. 残差分三类：真实泄漏、正常淘汰、数据采集缺口，只有真实泄漏才计价；手工环节默认当作疑似泄漏点。
3. 只算可回收金额（记录数 × 价值 × 往后的转化率，对滞留记录打折估算），每条记录只在第一次无解释退出的地方计一次；事后用实际回收额校准估算。
4. 一次只看一个漏斗、一个批次；无解释残差要低于容忍度（占位值 5%）。
5. 修复按“可回收金额 ÷ 修复成本”排序，责任归到流程或系统，不归到个人。

### CRM 字段治理

核心策略（5 条）：
1. 只治理收入关键字段（预测、分配、薪酬、高管报表会用到的）。
2. 每个字段一位具名负责人，归属用这个字段的部门，而不是录入的部门。
3. 按字段指定唯一的记录系统和冲突规则；同步时空值不覆盖已有值，但合规删除、客户撤回同意等合法清空走专门流程；第三方补全只填空值。
4. 执行手段的优先级：受限下拉 > 按阶段条件必填 > 默认值 > 权限 > 页面布局 > 硬性必填。
5. 治理靠例会而不是文档：定期委员会，抽 10–15 个字段核对，一致率 ≥ 95%。

### 收入数据治理战略

核心策略（6 条）：
1. 按对象类别分别指定记录系统（负责写入）、事实来源（决策读取的数）和负责人；先发布这张表，再考虑买工具。
2. 财务和销售的数字之争是定义问题，不是数据质量问题：先让各方签署统一口径，再写成有版本的定义。
3. 数据契约只用在少数“一坏就拖垮收入报表”的边界上，不全面铺开。
4. 身份主干：唯一账户 ID 加唯一人员 ID，用别名表映射各系统；精确匹配优先，模糊匹配交人工复核。
5. 运营模式按规模选：小规模以 CRM 为中心，大规模或按用量计费以数据仓库为中心。
6. 验收：不能出现两个团队各拿一个不同、又都说得通的 ARR 数字。

### 工具栈精简

核心策略（5 条）：
1. 先画收入工作流，再把工具对上去；按功能找重叠，目标是消除重复花费，而不是压低工具数量。
2. 裁决以业务价值为准，使用率只作诊断参考；员工自己买的工具先调查原因，判断是否代表没被满足的需求。
3. 工具清单取合同库、报销记录、SSO 日志、网络监测四个渠道的并集。
4. 用 Gartner 的 TIME 框架（容忍、投资、迁移、淘汰）给每个工具打分，并叠加续约日历定截止日。
5. 执行顺序：降席位或降档 > 消除重复 > 同类替换 > 平台整合 > 自建。

### 销售赋能

核心策略（5 条）：
1. 物料和一线销售一起做，用销售自己的语言，先给业绩最好的人试用。
2. 每个卖点都要落到收入、效率或风险上，并且销售能当场证明；“我们为什么能赢”要有赢输访谈等证据，没有就写成待验证的假设；写明在哪些情况下我们会输。
3. 处理现场异议：先确认是谁、原话、在哪个阶段 → 判断背后的真实顾虑 → 给一段能直接照说的回答，配一个证据、一个追问 → 确实不合适就收窄或放弃。
4. 赢输分析：赢单也要纳入；每单只记一个主因；报告附样本量，少于约 5 单只算信号。
5. 演示放在需求发现之后，只展示 3–4 个对应客户痛点的工作流，不挨个过功能。

### 潜在客户开发

核心策略（6 条）：
1. 先选赛道，不同赛道的评分规则不混用；先写出理想客户画像和“通过 / 淘汰”清单，再找名单。
2. 候选名单收集到最终需要量的 2–3 倍，多个来源交叉验证；宁少而准。
3. 每条判断附来源链接；“高”置信度需要两个独立来源；联系方式先验证，搁置超过 7 天再用时重新验证。
4. 热线索 = 强匹配 + 明确购买信号 + 能接触到决策人 + 已验证的联系方式；热、温、冷的比例是打分的结果，不预设目标比例。
5. 按账户分层投入：1 级前 25–50 个一对一；2 级按共同痛点分组；3 级一对多。
6. 合规底线：不批量抓取平台数据，记录每个联系人的来源，不按敏感属性分群。

### 企业销售

核心策略（6 条）：
1. 创始人亲自签下最初一批客户（嘉宾说法从 10 个到几十个不等），保住市场到产品的反馈环；跑通可复制的成交流程后再招销售。
2. 每个功能同时满足用户体验和组织治理要求（SSO、安全认证、权限、发票）。
3. 跨越鸿沟之后，叙事从“认同愿景”转为给实用主义买家可复制的方案。
4. 先诊断买家的痛点和业务风险，再演示功能。
5. 买家犹豫常常是怕选错，而不是缺紧迫感：先用试点、分阶段上线、退出条款等降低买家的决策风险，而不是加大施压。
6. 评估新销售看领先指标（会议量、新建商机），不等成交额。

### PLG 与销售结合

核心策略（6 条）：
1. 产品驱动增长和销售不是二选一，而是有先后地都做：产品铺开入口，销售聚焦高价值客户。
2. 用产品使用行为定义高意向线索（触达用量上限、邀请同事、同公司多个账户），优先级高于市场线索。
3. 叠加销售的信号：自助用户中出现大客户，开始要求单点登录（SSO）、安全审查、统一采购等企业需求。
4. 销售加入的时机看两点：自助流程是否已稳定；对手是否在用销售抢企业客户。有对手抢客时宜早不宜晚（Dropbox 是反面案例）。
5. 销售辅助是支持自助流程，不是替代；创始人先亲自跑通销售，再招专职销售。
6. 规模起来后，用第三方数据和自动化工具给高意向线索排序；早期先由人工筛选。
